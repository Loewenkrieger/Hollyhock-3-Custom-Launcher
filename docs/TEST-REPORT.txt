Hollyhock 3 Custom Launcher 0.5 - test report
Validation date: 2026-10-29

Scope
-----
HH3 launcher for installed Hollyhock 3 on OS 02.01.7002.0001.
Fresh big-endian SuperH build with the pinned GCC 15.2.0 toolchain.
Hardware testing: NOT performed. Calculator startup timings and persistent
MCS behavior still require verification on a real ClassPad.

Automated checks: 78 passed
--------------------------
21 UI controller/renderer checks, including touch capture, dragging,
   key repeat, scrolling, 25000 mixed events and framebuffer bounds.
 7 real GUI adapter checks, including a 1000-app menu, lazy detail queries,
   cached revisits and EXE launch of the preselected recent entry.
 4 discovery checks: HH3-only filtering, sorting, hidden files/directories,
   unsupported-only files and complete enumeration of 1000 apps.
17 real ELF metadata checks: buffered reads, cached getters, multiple
   segments, missing metadata, unterminated note values and repeat-safe
   rejection of truncated headers, overflowed sizes and invalid segments.
14 MCS history checks: round-trip storage, five-entry MRU, duplicates,
   missing apps, filename case, invalid paths, unavailable storage,
   write errors, maximum path lengths and 10000 malformed records.
 5 launch integration checks using the real main() and history code:
   restore history before selection, no write when closing, no write after
   failed loading, write before execution, non-fatal MCS write failure,
   display restoration and explicit errors after failed app execution.
 6 exit-result factory checks, including every mismatching caller byte,
   unexpected OS result constants, repeated completion and error dialogs.
 2 narrow target SH consumer checks against the freshly linked ELF and
   run.bin: the actual object/callback reaches the normal OS continuation;
   the null-result regression faults at the expected object dereference.
 2 target MCS ABI checks: SH compiler output returns 0x05000000 after a
   synthetic byte write to the SDK enum, and 0x05 for the byte declaration.

Host probes use AddressSanitizer and UndefinedBehaviorSanitizer, except
for the exit-result probe, whose fixed ROM address overlaps ASan shadow
memory and therefore uses UBSan. LeakSanitizer is disabled. OS entrypoints,
file enumeration, MCS and app execution are mocked where applicable.
The target instruction consumer does not emulate the complete calculator.

Build and distribution checks
-----------------------------

ELF32, big-endian, EM_SH, entry 0x8cfd0000.
App-code segment loading, cache maintenance and OS return behavior remain.
The linked image stays below the reserved app RAM boundary at 0x8cff0000.
The existing closed/open/empty renderer previews are pixel-identical;
the additional recent-app preview shows the recent-entry list styling.
ZIP CRC, embedded source snapshot, local Markdown links, metadata hashes
and inner/outer SHA256 manifests are checked before publication.
Release packages include tests-host.json and tests-target.json with the
actual outputs for their source inputs and target binary.
