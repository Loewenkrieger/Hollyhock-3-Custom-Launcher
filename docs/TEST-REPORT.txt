Hollyhock Dual Launcher 0.4 - exit correction

ROOT CAUSE
Version 0.3 returned nullptr after a successful launcher/app exit.
This hook replaces a dialog factory, not a void event callback.
The original OS 02.01.7002.0001 System-menu handler at 0x8015C898
immediately loads the returned object's vtable at +0x4C and calls its
method entry at vtable+0x18C. A null result therefore reads address 0x4C.
The old HHK2 main_bootstrap.cpp also documents the requirement to return
a dialog object.

FIX
After the unchanged destructor, symbol-map and runtime cleanup, successful
completion returns a static, trivial adapter for this narrow OS protocol.
Its sole consumed method returns DialogResultCancel (0x03EB) without
allocating, drawing, opening a window, touching hardware or requesting reset.
The native caller then branches to its normal continuation at 0x8015CF94
without committing a change to the Imaginary Unit system setting.
The object and callback remain valid after C/C++ runtime finalization.
No Casio heap object is allocated or leaked for this normal return.

The OS guard and 32-byte caller instruction fingerprint plus its settings
result constant are checked before using the adapter. Unknown caller/OS
versions retain the original native completion-dialog return path.
Nonzero application exits retain an explicit error-code dialog.
Close, title X and physical Clear all use the same successful exit path.
